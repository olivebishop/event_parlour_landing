# Event Parlour marketing site

Astro 7 + React islands + Tailwind v4, hosted on Atlasflow as a Node server: `bun run build`, then `bun run start` (`server.mjs`, listens on `$PORT`).

- `src/pages/` — routes. `src/layouts/` — `BaseLayout` (html/head) and `MarketingLayout` (navbar/footer).
- `src/components/SeoHead.astro` renders every meta, OG, Twitter, canonical and JSON-LD tag. Pages pass only `path`. Titles, descriptions and target keywords live in `lib/seo/page-meta.ts`: titles ≤ 60 chars, descriptions ≤ 158. Only state product facts the app states at https://app.eventparlour.com/.md.
- GEO/AEO: `integrations/agent-markdown/` writes a Markdown twin of every page (`/why-us.md`, `/index.md`) and `/llms-full.txt` at build time. It serves the same in `astro dev`, plus `/.md` and `Accept: text/markdown`. `/llms.txt` is generated by `src/pages/llms.txt.ts`. Wrap mock or decorative UI in `data-agent-skip` so it stays out of the Markdown. FAQ answers in `lib/content.json` feed the page, the FAQPage JSON-LD, llms.txt and /.md.
- IndexNow: after each deploy, `bun run indexnow` pings Bing and others. The key file is `public/56e50a8a9e6435355309971bffe721de.txt`.
- `components/`, `lib/`, `hooks/` — React components and shared code, imported via `@/…`.
- React components render to static HTML unless a page adds a `client:*` directive. A component without one ships no JS, so its nested interactive children won't work either.
- Islands don't share React context. Theme state is in `lib/theme.ts` (localStorage plus a window event), not a provider.
- Pages are prerendered at build time. Don't render the current time or locale-dependent values during SSR, because that causes React hydration error #418. See `components/download/use-local-clock.ts`.
- OG images: static PNGs in `public/og/`, generated from `src/pages/social-card/[...card].astro` by `scripts/generate-social-cards.ts` (Cloudflare Browser Run). When you add a marketing page, add it to `getOgPaths()` and `getOgContent()` in `lib/seo/og-content.ts`.
- `server.mjs` — production server: redirects and headers (ported from next.config.ts), the `/.md` agent view, then Astro's Node handler. Pages are prerendered; only `src/pages/api/contact.ts` runs on demand.
- Contact form: Resend from the eventparlour.com domain. Templates are in `emails/`, sharing the design files in `emails/shared/` with eventpalour_app/packages/email. Preview them with `bun scripts/preview-emails.tsx`.
- `og:video`: only the iMessage crawler gets it, and only on `/` (see `server/og-video.mjs`). The MP4 in `assets/og/` is served with byte ranges because iMessage requires a 206 response. Bump `OG_VIDEO_ASSET_VERSION` when you replace the file.
